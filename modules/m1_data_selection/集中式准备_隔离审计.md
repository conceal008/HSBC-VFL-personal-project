> 口径基准：用户 2026-09-28 的模块化、两方隔离和统一日志要求

| 审计项 | 原实现 | 判断与整改 |
|---|---|---|
| 原件保护 | 只读输入、前后哈希、新 run_id | 可保留此规则；重跑继续验证 |
| 两方数据不互知 | `load_source` 单进程读取完整表，`run_pipeline` 在同一内存生成双方矩阵 | 不满足隔离；改为可信离线投递后，各方只读本方输入并独立清洗 |
| 系统权限 | 同一用户的两个普通文件夹，无访问拒绝 | 不满足；增加内核文件读取/写入限制和禁网策略，实测越权被拒绝 |
| 参数与 Notebook | 两方参数集中在同一 state 文件，运行输出由中央保管 | 不满足；参数、清洗表和完整 Notebook 分别写入本方私有结果 |
| 标签边界 | Bob 导出 CSV 不含标签，但全表在上游进程可见 | 仅满足导出格式，不能证明运行隔离；系统限制全量源访问 |
| 划分信号 | Hillstrom 根据处理与结果联合分层 | 当前严格模式改为不依赖结果字段的记录哈希划分，避免把结果信息用于双方可见切分 |
| 统一日志 | 有指纹与清单，无统一目的/内容/模块状态索引 | 新增每次实验声明、阶段事件、私有产物索引、失败原因及最终状态 |
| 联邦协议与训练 | 从未执行真实 PSI 或训练 | 如实保持未完成；不得把处理成功解释为安全训练成功 |

## 旧结果如何处置

旧文件保留，不删除、不覆盖、不作为严格隔离实验的输入或结论。旧 Notebook 入口增加停止提示，避免误用。原产物只代表集中式预处理调试过程；新增合格与否依据 S1.P2 的独立证据，不追认旧实验。

## 重跑的信任边界

公开单表模拟必须由可信实验管理员先将字段投递给双方。该分发阶段能读原件，应单独登记；它不是联邦参与方。真实双机构部署时应由各机构自行接入本地源，不经过中央分发。

当前可实施的是同机操作系统访问限制，保护边界是参与方进程，宿主管理员仍可信。两台物理主机、不同管理权限及安全协议未验收前，不能声称满足真实两地部署或绝对零泄漏。新框架在训练门槛未满足时保持 `training_status: blocked`。

## 模块与运行入口

规范：`联邦流程模块与隔离要求.md`。可信实验管理员使用 `notebooks/S1.P2_isolated_simulation.ipynb`；它为每方启动独立沙箱，逐 cell 执行 `notebooks/S1.P2_party_preparation.ipynb`，各方输出只保存在本方目录。

统一实验日志在本地 `8-9月/实验日志/实验索引.md`。只记录固定状态、私有产物地址和允许的校验和，不聚合双方数据或预处理参数。
