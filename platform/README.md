# platform · 跨模块共享平台层

《项目维护约束 v2》1.2 与《模块 Loop 执行规范 v2》0.6 的分层要求（L1 设备层 → L6 治理层）在此落地。

| 目录 | 职责 |
|---|---|
| `devices/` | 设备/执行环境抽象 |
| `dataframe/` | 两侧各自的数据表抽象（不得跨方共享实例） |
| `operators/` | 算子层 |
| `components/` | 可复用组件（每个组件必须有 schema 声明与冒烟测试） |
| `orchestration/` | 编排层：批次、重跑、断点续跑、单方不可用降级 |
| `governance/` | 治理层：审计日志、合规元数据、同意状态。跨境调用运行时记录 9 字段 |

## 改动本目录的额外约束（6.5）

- 改动前必须检查是否有其他模块依赖（搜索引用）
- **`platform/` 的接口变更一律视为 breaking change**，须走 DR + 下游 approve + 保留旧接口 ≥1 个模块周期
- 审计日志本身不进 git（运行时产物），但**日志 schema 与写入代码必须在 git 里**且有测试保证格式正确

当前为空，等待第一个组件落地。
