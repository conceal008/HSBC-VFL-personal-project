# 联邦流程模块、隔离要求与实验日志

> 编写日期：2026-09-28 ｜ 版本：v2.0 ｜ 状态：当前执行要求
> 数据来源：用户本轮要求、维护约束第 2/9.1 节、隐语本机部署记录
> 口径基准：共同客户联合营销；本要求优先于 S1.P1 的集中式处理示例

## 模块职责与放行条件

| 模块 | 功能与本地输入 | 输出与权限 | 放行条件 |
|---|---|---|---|
| P0 实验登记 | 目的、假设、数据版本、标签时点、切分种子、运行环境和隔离模式 | 实验 ID、配置/代码指纹、允许披露清单 | 未登记不处理 |
| P1 离线模拟分发 | 仅对公开单表代理源做字段投递，不清洗、不拟合 | 各方独立只读输入；分发者为可信实验管理员，不属于联邦参与方 | 分发结束后参与方无权访问全量源或对方投递目录；真实机构数据不得经此中央分发 |
| P2 身份与隔离检查 | 各自启动环境、本方输入、越权测试目标 | 本方检查记录，中心仅收状态 | 读取对方输入/中间文件、写入本方原件/对方文件、访问全量源和未授权网络均必须失败；存在但不可读才算拒绝，文件缺失不算通过 |
| P3 本地清洗与标签 | 各方只读取本方字段；Alice 持有标签与必要的处理变量 | 各方清洗副本、字段质量报告；全部私有 | 排除事后字段；记录每步输入/输出哈希；双方不共享行级结果 |
| P4 安全实体对齐 | 经审计的标识与成熟 PSI 协议 | 仅向获准接收方披露交集；非交集不得集中 | 真实协议与身份认证通过；构造相同行号或本地集合运算不算 PSI |
| P5 冻结切分与本地拟合 | 对齐后的记录级切分协议、本方训练数据 | 各方训练/验证/测试矩阵、各自编码/填补参数 | 标签不得影响跨方可见划分；验证/测试不得参与拟合；有稳定客户键时优先客户级切分 |
| P6 基线与安全训练 | L0 本地基线、L1 允许的聚合信息、L3 密码学保护下的联合训练 | 模型份额各自保存；禁止中心拼接特征、公开标签/残差/梯度/完整权重 | 先验证基线与安全协议、会话认证、通信披露清单和攻击测试；任何未达标项目保持 blocked |
| P7 推理与评估 | 冻结测试集；标签与逐条预测仅在主动方或安全计算中 | 按预登记许可输出聚合指标及置信区间 | 不向 Bob 或中心公开逐条预测；至少 5 种子效果实验另行完成；模型输出泄漏也需评估 |
| P8 日志与验收 | 模块事件、私有产物清单、允许的摘要 | 统一实验索引、状态、证据路径；各方完整日志各自保存 | 目的/内容/中间数据/最终结果可追溯；失败也登记；仅全部必需门槛通过才标 complete |

当前先重跑 P0–P3 与本地输入准备部分的 P5。P4/P6/P7 仍待实现与安全验收；全流程状态不得写成训练成功。

## 隔离等级必须如实登记

- `directory_only`：单机目录分离，仅调试；**不满足本要求**。
- `os_sandbox`：内核限制文件访问与网络的独立进程；必须有实际拒绝记录。可用于当前本地输入准备；共享宿主管理员可信，**不是物理隔离**。
- `separate_vm`：独立虚拟机、磁盘、用户/密钥；无共享数据卷。共享宿主仍可信，**不是两台物理机**。
- `separate_host`：两台独立主机/管理权限、无共享文件系统，分别保存数据与密钥；用于模拟两地的目标部署形态。跨主机必须补双向身份认证、端口白名单和加密传输。

Notebook 只能通过隔离启动器运行本方处理；未通过隔离前置检查时直接报错。禁止为了跑通而取消沙箱、扩大到整个项目目录、挂载双方数据、把双方凭证交给中央控制器或把失败标为成功。

## “不泄漏”的具体边界

原始字段、标签、清洗后的行级数据、编码参数、逐条预测、未保护的梯度与残差不得发送给另一方或中央控制器。密钥不得共享。临时文件、日志、Notebook 输出、异常堆栈和模型检查点同样按本方私有信息处理。

必须预先列出允许披露的内容；本轮仅允许实验/模块状态、固定产物名称与校验和。校验和也可能揭示内容相等关系，属于明确允许的审计披露。未来若允许交集、样本规模或聚合指标，须逐项登记接收者与理由，不能默认全部 `reveal`。

不能对任意恶意方、宿主管理员、侧信道和模型推断攻击作“绝对零泄漏”承诺。当前本机重跑仅验收文件访问与禁网隔离；安全训练另依据具体协议和威胁模型验收。SecretFlow 的 SPU 是秘密计算运行时，并不能替代操作系统与部署隔离，见 [官方 SPU 设计](https://secretflow.readthedocs.io/en/stable/developer/design/spu.html)。

## 文件位置与统一实验日志

原始下载目录仍只读。每次运行建立新的实验 ID，三类本地产物分别存放：

1. `8-9月/联邦隔离输入/<实验ID>/<party>/`：从公开原件投递的本方原始字段，只读。
2. `8-9月/联邦隔离产物/<实验ID>/<party>/`：本方清洗表、冻结切分、编码矩阵。
3. `8-9月/联邦隔离结果/<实验ID>/<party>/`：本方 Notebook、预处理参数、校验、错误记录、环境与代码快照。
4. `8-9月/实验日志/<实验ID>/`：中心日志只包含目的、内容、配置/代码指纹、模块状态、各方私有产物地址及允许摘要；**不复制中间数据本体或私有统计到中心**。

实验日志至少记录：实验 ID、目的/假设、数据与许可来源、预测时点、模块顺序、隔离方式/威胁边界、参数与种子、输入版本、各阶段开始/结束及状态、中间数据地址/版本/哈希、最终状态/指标证据/未达标项、失败与整改、代码版本、旧实验取代关系。仅准备数据时，最终状态必须是 `data_preparation_only`；训练状态为 `blocked`，不能空着或推断成功。

`实验日志/实验索引.md` 统一维护可读索引，每个实验目录不可覆盖。公开仓库只提交代码、配置、协议规范和清除输出的 Notebook；本地完整实验日志与私有产物不得推送。
