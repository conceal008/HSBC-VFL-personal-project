## 入口与目录

入口是 `notebooks/S1.P1_uci_preparation.ipynb` 与 `notebooks/S1.P1_hillstrom_preparation.ipynb`。Notebook 按顺序展示运行指纹、划分统计、缺失情况、校验及解释边界。可复用代码在 `components/data_preparation.py`，每套数据的字段归属、排除原因、标签及种子在 `configs/`。

```text
HSBC-VFL-personal-project/modules/m1_data_selection/
├── components/                  处理逻辑与 Notebook 执行器
├── configs/                     数据版本、字段与切分配置、环境锁
├── notebooks/                   无数据输出的可重跑源文件
└── tests/                       使用程序构造样本验证保护措施

8-9月/
├── 运行准则.md                  用户指定的本地运行约束
├── 数据集/                      原始输入；本框架只读
├── 数据处理环境/v1/             独立 Python 与 Notebook 内核
├── 数据处理产物/<dataset>/<run_id>/
│   ├── clean_features.csv       清洗后的新副本，无标签
│   ├── split_assignments.csv    冻结记录划分
│   ├── alice/                  train、validation、test，含 label
│   ├── bob/                    train、validation、test，无结果字段
│   └── psi_inputs/             构造部分重叠的训练输入，尚未执行 PSI
└── 数据处理运行结果/<dataset>/<run_id>/
    ├── *.executed.ipynb         带输出的实际运行 Notebook
    ├── source_snapshot/        代码、配置和源 Notebook 快照
    ├── fingerprint.json        输入/配置/代码哈希、Git 版本、依赖
    ├── data_contract.json      字段、预测时点、解释边界、训练字段白名单
    ├── preprocessing_state.json 仅训练集拟合的中位数、缩放与类别字典
    ├── data_manifest.json      新数据的 SHA-256 与大小
    ├── checks.json             保护、划分及对齐校验
    ├── partition_summary.csv、missingness.csv、overlap_audit.json
    ├── PREPARATION_READY.json  数据准备全部校验通过才生成
    └── NOTEBOOK_COMPLETED.json 所有 Notebook cell 完成才生成
```

存在错误时保存 `FAILED.json` 及已执行的 Notebook（若已成功建立运行目录），不产生完成标志；已有运行不覆盖。

## 运行

本机使用独立环境，保持隐语已锁定的 Python 3.10 环境不变。数据以 CSV 交换，后续隐语按字段契约读取。

```bash
cd '/Applications/总文件夹/汇丰/HSBC-VFL-personal-project'
'/Applications/总文件夹/汇丰/8-9月/数据处理环境/v1/bin/python' \
  modules/m1_data_selection/components/execute_preparation.py \
  modules/m1_data_selection/notebooks/S1.P1_uci_preparation.ipynb
```

将 Notebook 文件名改为 `S1.P1_hillstrom_preparation.ipynb` 可处理 Hillstrom。每次执行自动建立新目录并打印带输出文件的位置。

在其他电脑上用 Python 3.11 建独立虚拟环境并安装 `configs/preparation_environment.lock`。默认路径相对仓库父目录的 `8-9月`；可以设置 `VFL_RAW_ROOT`、`VFL_DERIVED_ROOT`、`VFL_RESULTS_ROOT`，三个目录须互不包含，且全部位于仓库外。交互式打开源文件时使用同一环境的内核；推荐用执行器保存完整运行副本，避免手工保存输出到公开仓库。`VFL_REPO_ROOT` 可显式指定源码仓库。

## 处理规则

1. 核验精确表头与标签取值；每个源字段都必须声明用途或排除原因。
2. 根据原始文件哈希和行号生成稳定记录键。其作用限于同一文件内记录对齐，不识别真实客户。
3. UCI 按源顺序向前留出；Hillstrom 按处理组与结果联合分层。当前比例及种子见配置。
4. 各方仅用训练记录拟合中位数、类别字典和标准化。验证/测试出现新类别时编码为全零，不重新拟合。
5. Alice 输出包含 `label`，Hillstrom 另含 `treatment`；Bob 无标签或处理变量。读取训练特征时必须使用 `data_contract.json` 的白名单，不能使用“除 ID 以外全部列”。
6. `psi_inputs` 的交集占并集比例由配置定义，仅使用训练记录，双方顺序被打乱。它用于下阶段隐私集合求交（Private Set Intersection，PSI）接入，不是已完成的密码学协议。
7. 运行前后核验原件哈希；结果与新数据分别写入独立目录；两个相同配置运行应生成相同数据哈希，时间与 run_id 可以不同。

## 范围与下一步

本版本覆盖 UCI 与 Hillstrom 的数据准备，未运行联邦训练或效果比较。UCI 的宏观字段通常可公开取得，后续要增加本方可得信息对照；UCI 缺稳定客户标识，无法承诺客户级互斥。Hillstrom 两种邮件处理保持独立，不隐式合并。

同机脚本可读取两方输入，当前目录分离只用于研究复现与文件管理。后续接入隐语时须将各方读取器部署到各自运行环境，并补齐权限、协议、安全及性能验证。

其他数据集按各自标签和预测时点新增配置及必要的适配器。Santander 产品月度面板需专门构造下一月新增持有标签，不能直接套用单表二分类配置。S1.P1 是用户新增的工程前置步骤，不替代 S1.1–S1.9 的正式选型和四切分验收。
