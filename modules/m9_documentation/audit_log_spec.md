# M9 · 跨境调用审计日志规格

- 产出日期：2026-09-04（S9.1）｜ 状态：规格已定，**实现待真实环境**

## 九字段（每次跨境调用必记）

| # | 字段 | 说明 | 为什么必须 |
|---|---|---|---|
| 1 | `timestamp` | 调用发生时刻（带时区） | 事后追溯的时间锚点 |
| 2 | `direction` | `cn→hk` / `hk→cn` | **方向决定适用哪套法规**，不可省 |
| 3 | `object_type` | 对象类型，对应 `results/cross_border_flow_registry.csv` 的 CBF 编号 | 让日志能与跨境清单对上 |
| 4 | `volume` | 本次涉及的数据主体数与数据量 | 出境机制按人数分档，无此字段无法判断门槛 |
| 5 | `legal_basis_ref` | 引用的合规路径 ID | 每次跨境都要能说清依据哪条路径 |
| 6 | `consent_batch_id` | 对应的同意批次 | 同意撤回后要能反查哪些调用受影响 |
| 7 | `caller` | 发起方系统与操作者 | 责任归属 |
| 8 | `config_fingerprint` | 运行指纹（配置内容摘要） | 让「这批名单是哪个配置跑的」可回答 |
| 9 | `degraded` | 本次是否处于降级状态 | **静默降级是本项目识别出的具体风险（R6）** |

## 保存与访问

- 日志本身**不进 git**（运行时产物）；**日志 schema 与写入代码必须在 git 里且有测试**
- 保存期限：待合规责任人确定（本项目无人可定）

## 与故障注入的对应

| 字段 | 由哪项故障注入验证 |
|---|---|
| `degraded` | F2 单方下线降级 |
| `config_fingerprint` | F5 数据延迟批次一致、F6 重复执行幂等 |
| `consent_batch_id` | F7 同意撤回剔除 |
