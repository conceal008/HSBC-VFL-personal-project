# S6.P4 G3 五臂对比 FedAds 补充冻结

> 编写日期：2026-10-27 ｜ 版本：v1.0 ｜ 状态：frozen（机器可读部分 `configs/s6_p4_fedads_addendum.yaml`）
> 上位：S6.P3（frozen，S5.G0）｜ 决策记录：DR-M6-002 ｜ 授权：DR-GOV-016、DR-GOV-017 · D-1/D-3
> 技术侧自评，未经法务复核（W-001）。本文件不含任何行数据或逐行结果。

## 为什么要补

DR-GOV-017 把第二组证据由 HSBC mock 改为 FedAds（官方纵向切分）。S6.P3 对 FedAds 只写了「按用户、封存段为按时间最晚的一段」，核对本机文件后有三处无法照写执行：

- 没有时间列，按时间划封存段做不到；
- 没有显式用户号；`l_u_fea_1` 近乎每行一值，可作用户号；
- 被动方（5 个低基数列）没有自有标签，B_T2 不适用。

另外主动方有十万级基数的标识类列，S6.P3 的编码对它没有规定。

## 写定了什么

| 项 | 写定的内容 |
|---|---|
| 双方 | 主动方 `l_*`（16 个特征列，持转化标签）= 内地；被动方 `f_*`（5 列）= 香港 |
| 用户与分组 | 用户号加盐哈希分 10000 桶；训练 [0, 580)、内层验证 [580, 810) 取自训练文件；开发评估 [2000, 2535)、封存段 [5000, 5535) 取自测试文件；四组用户两两不相交 |
| 开发评估规模 | 按训练文件正例率 0.59% 与测试文件每桶行数一次算出 535 桶，期望约 770 个正例行（目标 700，安全系数 1.1） |
| 训练规模 | 约 15 万行训练、6 万行内层验证（隐语 SGB 单进程耗时与行数近似成正比） |
| 编码 | 主动方训练组内超过 1000 个不同值的列做频数编码，其余序号编码；不用目标编码；用户号不作特征 |
| L1 | 分段 = 主动方 4 个低基数用户列的组合；香港返回分段内各类别占比；k 按不同用户数计 |
| 其余 | 臂、seed、20 组调参候选、口径 v1、两层重抽样（簇 = 用户）、停止规则全部继承 S6.P3 |

## 冻结前已经做了什么

- 本机文件指纹：两个 ZIP 与 `8-9月/数据集/MANIFEST.sha256` 一致；展开的 CSV 与 ZIP 内文件 CRC32 一致。
- 按用户号筛选（不读标签）：训练 151,281 行、内层验证 59,370 行、开发评估 129,489 行；三组用户互不相交（已核对）。
- 用冻结版组件在本机重跑筛选，解压后内容与首次筛选逐字节相同。
- 只看过训练组的正例率与编码基数；**开发评估集的标签在冻结提交之前没有被计算或查看**。
