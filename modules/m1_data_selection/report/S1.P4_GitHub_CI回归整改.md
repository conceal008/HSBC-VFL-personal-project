## 修复前结果

本机 macOS 全仓门禁：164 项测试通过，核心逻辑覆盖 96.1%，47 项回归全部通过。修复前首次 GitHub Linux CI 因 Ruff 未锁定失败（详见上一份 S1.P3 报告）。锁定 Ruff 后的第二次 GitHub CI，其余 7 个门禁均通过，但 regression 作业 **45 通过 / 2 失败**：

1. PR regression job 检出了 GitHub 合成 merge ref；HEAD 自检看到合并提交后按设计跳过，却被回归用例判为失败。
2. 代码质量回归夹具只建了 `modules/`，新版 MyPy 仍被传入缺失的 `platform/` 路径，Q2 阻断。

## 修复内容与本机复核

- `ci/check_code_quality.py` 只将实际存在的 `modules/`、`platform/` 目录交给 MyPy；两个目录都不存在时明确报错。
- `requirements.txt` 将 Ruff 和 MyPy 固定为 0.12.0 与 1.17.1，与仓库 lock 一致。
- GitHub Actions 的 regression job checkout PR head SHA，避免对合成 merge ref 做 HEAD 自检；将旧的 33 组提示修为 47 组。
- 修改后本机全门禁重新通过：164 tests passed、覆盖率 96.1%、回归 PASS=47 / FAIL=0；门禁 6 保留四项已说明的隐私 Notebook 输出警告，但门禁通过。

此报告不证明跨主机隔离、真实 PSI 或安全联合训练。
