## 我的判断与理由

1. **为什么第一步是初始化而不是 M0 的 S0.1。** 三份规范的原则一是"仓库是唯一事实来源，任何未写入仓库的知识视为不存在"。
   在仓库存在之前，S0.1 的产出无处提交、无法进台账、无法过门禁——这一步不做完，后面每一步都不合规。

2. **为什么仓库另起干净目录而不是把历史目录 git init。** 历史目录 `/Applications/总文件夹/汇丰/` 内含真实数据集
   （IEEE-CIS 全量、FedAds）与真实/半合成数据派生产物，属 L-禁止 / L-受限。物理隔离比 .gitignore 更可靠——
   后者一条规则写错就是不可逆泄露，尤其在 Public 仓库下。

3. **为什么门禁 1 与骨架同批上线，其余五个门禁推到下一步。** 门禁 1 防的是本项目唯一不可逆的错误：
   真实数据/凭证进入 git 历史（2.4：用新提交"覆盖"没有用）。其余门禁校验元数据与一致性，
   在第一条业务提交出现之前没有校验对象，晚一步上线不产生风险敞口。

4. **为什么 `cross_border_assets.yaml` 只放空模板。** 填充它是 M0 的 S0.2/S0.3/S0.4。
   初始化步骤若顺手预填八类资产，就侵占了后续三步的信息增量，且那三步的自评会变成"重组已有信息"（D4=1）。
   划界比省事重要。

5. **可见性偏离如实登记而不是消化掉。** 规范 1.1 要求 Private，仓库实际为 Public，所有者在被明确告知该条款后
   选择保持。按禁止事项第 16 条，不能改规范正文让它"看起来一致"，只能登记为已知偏离 + 补偿控制 + 复审触发条件
   （DR-GOV-001）。

## 试过但失败的

- 生成模块文档的脚本最初用 ASCII 双引号写中文引文，Python 语法报错；改用「」后又被自动替换脚本误伤了几处
  字符串边界（把 `","` 变成 `「,」`）。已全部修正并核对生成结果。**教训：后续凡在 Python 字符串里写中文引文，
  一律用「」，不要用 ASCII 双引号。**
- `check_secrets.sh` 第一版用了 `mapfile` 与 `set -u`，在 macOS 自带 bash 3.2 上直接崩溃；改为 while-read
  填数组并去掉 `set -u`。第二版个人标识扫描用 `|` 作"模式|标签"分隔符，而正则本身含 `|`（或），
  导致模式被截断成 `(^`，手机号漏检。改用 `@@` 分隔并补了构造样本回归测试才发现。
  **教训：门禁脚本必须用构造样本验证"能拦住"，只验证"不误报"是假通过。**
