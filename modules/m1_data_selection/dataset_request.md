## 三条纪律（下载前先读）

1. **数据永不入库。** 本仓库是 Public，且《维护约束 v2》第 2 部分禁止提交真实数据、
   合成数据与任何派生统计量。下载的文件放在**仓库之外**，只有数据卡、生成器、配置与种子进仓库。
2. **放在仓库外的固定位置**，建议：`/Applications/总文件夹/汇丰/datasets/<数据集名>/`。
   路径写进本机 `.env` 的 `DATA_ROOT`（`.env` 已在 `.gitignore` 中，不会被提交）。
3. **许可先看清楚。** 下表中多数为 **CC BY-NC-SA 4.0（禁商用）**，
   与项目历史阶段用过的 FedAds 相同。结论只能表述为**学术/代理验证**，
   不得作为商业用途的依据——这一条会写进每个数据集的数据卡。

## 优先级 P0 · 没有它就走不下去

### 1. Criteo Uplift Prediction

| 项 | 内容 |
|---|---|
| 为什么要 | **决策 D-1（纳入增益评估）的硬前提**。它是少数带**随机对照**的公开数据集——没有随机分流就算不出真实增益（uplift），而 S0.1 的业务最小可行规模 N_eff ≥ 30,000 正是按双臂随机对照推导的。缺了它，整条增量评估链路无法验证 |
| 下载 | <https://ailab.criteo.com/criteo-uplift-prediction-dataset/>（亦可用 Hugging Face 镜像 `criteo/criteo-uplift`） |
| 体量 | 压缩包约 **297 MB**，解压后约 **3.55 GB**；约 2,500 万行 × 11 特征 + treatment + 2 个标签（visit / conversion） |
| 许可 | **CC BY-NC-SA 4.0**（署名-非商业性使用-相同方式共享） |
| 注意 | 广告场景，特征语义**不可迁移**到跨境理财——它的用途是验证「增益评估链路本身对不对」，不是验证业务结论 |

### 2. Hillstrom MineThatData E-Mail Analytics

| 项 | 内容 |
|---|---|
| 为什么要 | 同样带随机对照，但**只有约 6.4 万行**——用来先把 uplift / Qini / AUUC 的评估代码跑通，再上 Criteo。先用小数据打通链路能省掉大量调试时间 |
| 下载 | 搜索 "MineThatData E-Mail Analytics And Data Mining Challenge dataset"；`scikit-uplift` 亦提供 `fetch_hillstrom()` 直接下载 |
| 体量 | 约 **1–2 MB** CSV |
| 许可 | 以下载页说明为准（公开可用于研究），须在数据卡中如实记录 |
| 注意 | 电商邮件营销场景，同样不可迁移语义 |

### 3. Santander Product Recommendation

| 项 | 内容 |
|---|---|
| 为什么要 | **语义最贴近本项目**：多产品交叉销售、**月度面板**、产品持有序列——正对应命题里的「首次成功申购某产品」。**它是校准基线转化率（决策 D-3 的 3.0% 假设）最合适的来源**，而基线转化率直接决定 N_eff 的量级（1% → 8.5 万，5% → 1.6 万） |
| 下载 | Kaggle 竞赛页 `santander-product-recommendation`（需 Kaggle 账号并接受竞赛规则） |
| 体量 | 训练集约 **2 GB**（以下载页为准） |
| 许可 | Kaggle 竞赛规则，通常限研究/非商业用途，须在数据卡中如实记录 |
| 注意 | 单机构、无跨域、无随机对照——**不能用它算增益**，只能用来校准转化率与验证面板结构 |
